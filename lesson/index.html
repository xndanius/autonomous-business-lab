Step 2 · Build a first version

Build it in five testable steps.

Use your six lines as the specification. Build one small path all the way to a real result before adding more features.

1 · Input
Pick one real user and one request you can handle. Save a concrete example input and write the useful output they should receive. Start with a form, message or scheduled data source you have permission to use.
2 · First result
Ask your coding agent to make the smallest working path from that input to that output. Run it yourself once. Show the result to five people outside your team; find out whether it is useful.
3 · Check
Save good, bad and edge-case inputs. Define a pass/fail rule and test that it catches the bad results. Choose a safe failure action: a bounded retry, holding delivery for review, or stopping. Test the failure path too.
4 · Run again
Add the trigger or daily schedule, a running server, saved run status and delivery. Record what has already been sent so retries do not send duplicates. Test a restart and a failed delivery. Set limits, alerts and a stop control before leaving it unattended.
5 · Measure
Record real users, returning users, successful and failed deliveries, cost per useful result, and minutes of manual work. Review the evidence daily. Test one change at a time against saved cases and real user feedback.

A laptop script stops when its runtime stops. A hosted service still needs working credentials, scheduling, monitoring and someone responsible for exceptions. Keep the templates below with your project.
