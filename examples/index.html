Example 1 · Built for the lecture

The 60-Second Startup

A request starts a cloud workflow: AI drafts a startup concept, a separate model call reviews it, and a passing page gets its own link. The page is a prototype: its proposed business, price and tool integrations still need to be tested and built.

Grow
A “Make your own” link invites the next user. Whether people use it must be measured.
Serve
Request → draft → check → deliver. Code fixes this sequence; a failed check allows one repair and another check, then stops.
Check
Code checks the format; a separate AI call reviews relevance and safety. Both can miss mistakes.
Improve
After 15 ratings, it can test new producer instructions on three fixed prompts. Keep them only if the comparison scores higher; this does not retrain the model or prove better customer outcomes.
Control
People set the scope, budget and stop rules and maintain the service. The old board’s “human touches” field is fixed at zero, so it is not a measurement of manual work.

Example 2 · Cloud workflow with hourly opportunities

While You Sleep

An ideas channel. A scheduled opportunity starts research and drafting from public sources. Review and source gates decide whether a candidate can be published. A slot may finish without a post.

–research candidates logged
–posts published
–estimated model cost · public log
–rule-test records / adopted
–last published
–last run
Grow
The public feed makes published ideas available to readers. Distribution settings and audience growth are separate things to verify.
Serve
Due slot → research → draft → check → publish or skip → save the run record.
Check
A separate review plus source, format and duplicate checks gate publication. A pass is not proof of market demand or profit.
Improve
Proposed rule changes are compared with the current rules on saved examples. Only a passing comparison can replace them.
Control
People set the publishing policy and budget. Public records show outputs and attempts; logged cost is an estimate, not a billing statement.

Example 3 · Recorded local creative run

The Long Run

An AI agent wrote and drew this comic, starting from one ordinary trail run in the Vilnius forests. A scheduled attempt supplied the last image and a short recap; the agent created and inspected a page, then saved it and the next handoff.

Pages
74, drawn on 11 October.
Trigger
A five-minute attempt when the previous job was idle. A failed attempt added no page.
Memory
The last image, story recap and cast, saved for the next attempt.
Check
The creating agent inspected continuity and the saved image. There was no independent semantic reviewer.
Limit
New pages needed the Mac awake and Codex connected. These 74 pages are a dated archive; a dependable service needs a runtime available when its users need it.

A way to inspect any of these examples

Four questions to ask

Grow, Serve and Improve name three business jobs, not three required agents. Start with one useful routine; use people, code or AI where each helps.

What starts it?

A request, due time or other event.

What is checked?

Identify the code, creator inspection or independent review—and what it can miss.

What is saved?

Find the progress, result and handoff used by the next run.

Who stays in control?

Name the person who sets limits, handles exceptions and can stop it.

Example 5 · Cloud conversation with bounded AI turns

The class simulation

The conversation runs for real; the students are fictional personas using one configured model. Each selected persona gets a separate model call, chooses words and an allowed action, and reacts to the shared history.

Trigger
A scheduled tick selects a few speakers.
Loop
Read profile, board and chat → choose a message and action → enforce the rules → save → let the next students react.
Check
Code enforces voting rules, action limits and valid targets. These are game-rule checks, not independent fact checks.
Memory
The shared conversation and idea board, plus each persona’s recent messages.
Limit
“In production” means voted through inside the simulation. It does not show a real team, paying customer or launched business.

7 · Starting points to adapt

No idea yet? Start from a real user.

Seven proposed directions from the lecture. Each describes a routine you could try to automate. Scope, demand, prices and four-week feasibility need testing with people you can reach.

Browse the real students’ workshop submissions →

For bar-goers in Riga

Every bar in Riga, with a board

A short, fair review of every bar, plus a small board where regulars post tips and meetups.

Loop
Every day → opening hours, menus and events → reviews updated → check → live. New posts → moderation check → live.
Check
Every fact matches a source: the bar's own page or a visit. Insults, ads and personal data are held for review.
First test
30 bars in Old Riga. 50 students on the board for one week.
For SSE Riga students

A student radio that never sleeps

A web radio that runs itself: royalty-free music, campus news, events and shout-outs.

Loop
Schedule → events and shout-outs collected → AI host writes and voices short segments → check → stream
Check
Every news item has a source. Only royalty-free or licensed music. Shout-outs are checked before they air.
First test
One hour a day for one week. Count listeners and shout-outs.
For students curious about the future

A daily newsletter on autonomous organisations

Every morning, three things that happened in AI-run businesses, explained simply.

Loop
Public sources → pick three → summarise → check → send at 8:00
Check
Every claim links to its source. No invented numbers or quotes.
First test
Seven issues to 30 subscribers. Count opens and replies.
For anyone who wants to be inspired

Inspiring people tracker

Pick the people who inspire you, and get a short daily note on what they did, said or built.

Loop
Public posts and news → match to the people you follow → summary → check → daily digest
Check
Public sources only. Every line links to its source. Nothing private, nothing invented.
First test
20 people, 30 readers, one week.
For students looking for an internship

Internship scout

Fresh internships in the Baltics, matched to each student's profile, every morning.

Loop
Company pages and job boards → match to profile → check → morning alert
Check
The link works, the deadline has not passed, and the location and language fit.
First test
30 SSE students for one week. Count applications sent.
For dog owners in one neighbourhood

A local network for dog owners

Walks, meetups and lost-dog alerts for one neighbourhood, with a daily park update.

Loop
New posts and alerts → match by area and time → daily update → moderation check → live
Check
Lost-dog alerts go out fast, with a photo and an area, never a home address.
First test
One neighbourhood, like Āgenskalns. 30 owners from a local group.
For a sports club

The beast leaderboard

A live leaderboard and weekly awards that make a club's training visible and fun.

Loop
Results from a sheet or an app export → leaderboard → check → weekly awards post
Check
No result counted twice. Odd results go to the coach before they count.
First test
One SSE sports club for two weeks.

8 · Additional reported failure cases

Three lessons from real makers

Each one breaks one of the six things the challenge asks for.

No real user

Nine months of building. Almost no users.

A maker reports building a complete AI video tool and getting almost no users after nine months. A working pipeline is not demand.

Talk to real users before you build.

Source ↗
No check

The AI invented numbers in a CV.

A commenter reports that an AI CV tool added performance numbers the person never gave. A more convincing sentence is not a true one.

Check facts against the input before you deliver.

Source ↗
Hidden manual work

Auto-posting still needed people to step in.

An automatic video-posting tool's own FAQ discusses low views and suggests posting from the account by hand. The loop stops before the result the user wants.

Count every manual fix as part of your loop.

Source ↗

Collected in the Autonomous Business Field Guide, 7 October 2026. Makers' reports are not audited.
