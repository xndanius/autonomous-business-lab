01 · The way you work

Direct the work.
Stay close to the evidence.

You own the user, the goal and the decisions. Agents help you research, build and test. A workflow repeats the useful routine.

  1. 01

    Find a real job

    Talk to five people you can reach. Watch how they solve it today. Ask AI to organise the evidence and challenge your assumptions.

    Keep: one user, one recurring need, real examples.

  2. 02

    Write the brief

    Give the agent the goal, context, constraints and a clear finish line. Attach examples. Ask for a short plan and the next smallest useful step.

    Keep: a brief the team can reuse.

  3. 03

    Build one complete slice

    Make one real input become one useful result. Ask the agent to run it, test it and show what changed. Try it yourself, then watch a user use it.

    Keep: a working link and evidence of actual use.

  4. 04

    Check the awkward cases

    Save 5–10 examples: normal requests, missing input, duplicates and past failures. Use fixed rules for facts you can test, plus a separate review for judgment.

    Keep: pass/fail results, not “the AI says it works”.

  5. 05

    Put the routine in the cloud

    Choose its trigger, allowed actions, retry limit and stop condition. Log every run. Keep human approval for sensitive actions and exceptions.

    Keep: a daily run, a cost cap and a stop button.

  6. 06

    Improve one thing

    Review repeat use, failures, cost per useful result and your minutes. Change one thing. Compare old and new on the same saved cases before shipping.

    Keep: one measured improvement each week.

A starting brief you can copy Goal → Context → Constraints → Done

Replace the brackets. Keep the brief, examples and decisions in your project files so the next session can pick up the work.

GOAL
Help [five named testers] get [one useful result] every [day/week].

CONTEXT
They currently [do this]. Here are real examples, approved sources and what we learned: [attach].

CONSTRAINTS
Use the current project and the smallest useful change. Daily budget: [amount]. Keep secrets out of code. Agree before the first live send, spend or data change. Then work within those limits; ask before exceeding them. Flag missing facts.

DONE WHEN
One input becomes a checked result. These examples pass: [attach]. Show the working result, checks, changed files, remaining risks and how to stop it.

First: propose a short plan. Then build and verify the first slice.

02 · Choose your tools

Start with a small stack.

One assistant. One coding agent. One place for your evidence. Add a cloud runtime when the job is ready to repeat.

Think & research

ChatGPT, Claude or Gemini

Use the assistant you already have. Explore options, understand unfamiliar work and draft interview questions. Give it your evidence; ask for sources and uncertainty. On eligible paid plans, Claude Desktop can also work on files in a folder you allow; this was called Cowork.

Cost (checked 13 Oct 2026): Free tiers, with optional paid plans: ChatGPT, Claude, Gemini.

Leave with: a decision, a reason and a next test.

Build & verify

Codex or Claude Code

Let an agent work in your project: edit files, run commands and tests, and fix failures. Give it a small deliverable and an explicit way to verify it.

Cost (checked 13 Oct 2026): Codex is limited on Free and Go, included in Plus ($20/month), with more usage on Pro.

Cost (checked 13 Oct 2026): Claude Code is in paid Claude plans from Pro ($20/month, about $17/month billed yearly); not on Free.

Leave with: a working slice, a readable change and test evidence.

Connect & repeat

n8n or a hosted job

Connect a form, schedule, model call, check and delivery. n8n provides a visual workflow; an agent can also write a small program that runs on a server.

Cost (checked 13 Oct 2026): n8n Community Edition is free to self-host; hosting and connected APIs may cost extra.

Leave with: a trigger, a run log, a retry limit and an owner.

Make useful media

Your assistant or Higgsfield

Start with your assistant for simple visuals. Add Higgsfield when video is part of the product. Specify audience, format, reference and what a good result must show.

Cost (checked 13 Oct 2026): Limited free tier; paid plans from about $9 to $15/month. Prices change often, so check the pricing page. Commercial use is allowed under its terms.

Leave with: one useful asset. Check accuracy, consent and rights before publishing.

Your team's memory

A shared document or sheet holds interviews, source links, test cases and costs. GitHub keeps versions of code and briefs. Save decisions there; do not rely on one long chat.

Your running costs

Start free where possible. Pay for one bottleneck. Budget separately for subscriptions, API calls and hosting; check how your chosen route is billed. Challenge support →

Useful extras, when you have a reason Sources, long tasks, deployment

Questions about your sources

Gemini Notebook (formerly NotebookLM) grounds answers in selected sources and provides citations. Good for interview notes and course material. Open the cited passage and check the claim.

Long research tasks

Grok Bot offers a cloud computer for delegated work. Review its work and permissions; give it a bounded task.

Cost (checked 13 Oct 2026): From $30/month on The X Subscription Premium; existing SuperGrok and paid Cursor plans also qualify.

Tagging @bot on X is not available for EU-based accounts, including Latvia.

A public URL

GitHub Pages fits static class demos and project documentation. Choose an appropriate app host for a customer-facing service or backend.

Cost (checked 13 Oct 2026): Pages and Actions with standard hosted runners are free for public repositories.

A dependable runtime

n8n Cloud is managed hosting with a trial, then paid plans. Community Edition is free to self-host; the server and upkeep are yours. Actions schedules can be delayed or dropped. Choose a runtime that meets your users' timing needs.

03 · A loop in practice

An internship scout for five classmates.

Test the result by hand first. Then make this small routine repeat. The tools serve the job.

  1. TriggerEvery weekday

    A hosted schedule starts the run.

  2. CollectApproved sources

    Read employer pages the team selected.

  3. MakeA short shortlist

    Match roles to the student's stated interests.

  4. CheckLinks, dates, fit

    Reject expired roles, duplicates and unsupported claims.

  5. DeliverOne opted-in digest

    Send once; keep failed deliveries visible.

  6. LearnUseful or ignored?

    Record clicks, feedback, cost and your minutes.

Before it runs alone

Approve the first editions. Save normal and broken examples. Put secrets in the host's secret settings; give each connection only the access it needs.

Make limits real

Enforce a daily spend cap and limits on results and retries in the workflow. Stop or ask you when checks fail. Put the stop control and failure log where the team can find them.

Grow · Serve · Improve

Invite the next five users with a useful sample. Deliver a checked shortlist. Each week, test one change against the same cases and user feedback.

Keep your first loop simple. Add parallel agents or more tools when one measured bottleneck justifies them. Build the control panel →

04 · Keep up without losing the day

Use X as a radar.
Turn a claim into a test.

A launch post is a lead to investigate. Your own result decides whether a new tool earns a place in the stack.

  1. 2 min

    Scan a small List

    Use a private X List: the tools you use, two builders and people in your users' world. Read that instead of an endless feed.

  2. 3 min

    Open the original

    Find the official release or docs. Check the date, availability, price and limits. Grok can help find sources; read them yourself.

  3. 4 min

    Try one saved task

    Use the same input as your current tool. Compare quality, minutes and cost. Queue a bounded experiment if it needs longer.

  4. 1 min

    Keep it or skip it

    Write one line: claim → evidence → result → decision. Adopt it only if it improves your product. Then return to building.

Set up your X List A small starter set

Create a private List and pin it using your existing account. Pick a few accounts, not every one below.

Add local founders, customers and people doing the job you want to improve. Product demand is a signal too.

Ask Grok: “Find the original announcement for this claim. Link the official docs. What is available to me, and what would I need to test?” Keep private work out of public replies.
